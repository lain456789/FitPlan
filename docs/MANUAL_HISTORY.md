# 手动补录训练

v0.6.2 起支持将事后补录的训练保存到本地 SQLite 历史，沿用现有表结构。

## 使用流程

1. 在底部打开「记录」，点击右上角的「+ 补录」（英文「+ Add」）。
2. 选择实际训练日期和结束时间，最晚可选当前时间。如果所选日期已经有训练记录，按提示重新选择日期。名称选填，留空时按日期生成。时长也可留空，可以只填小时、只填分钟，或两者都填。
3. 点击「添加动作」，按名称或部位搜索已有动作，支持内置和自定义动作。自定义动作需先在动作库创建。重复选择会提示该动作已存在，并保留先前录入的组数与数据。
4. 每次显示一个动作，左右滑动可切换。为当前动作添加实际训练组，填写 0–1000 kg 和 1–100 的整数次数。自重可填 0，难度选填。每组可单独修改、删除。
5. 点击页面底部的「保存到历史」写入数据库，随后可查看历史详情。每次最多 30 个动作，每个动作可录入 1 至 20 组。

返回记录页或切换页面后，重新点击「+ 补录」可继续填写草稿。系统重建 Activity 时也会恢复表单。页面底部的「放弃补录草稿」与「保存到历史」并排，确认放弃后会清除草稿。取消单组编辑会保留该组原有数据。数据库写入失败时也会保留草稿。

## 与现有数据的关系

- 每次补录使用独立 UUID，只保存 history，不创建或覆盖 plan、active、checkin，不影响进行中的训练。
- 历史列表按 finished 倒序排列，事后补录较早训练不会因为录入时间较新而排在最近训练之前。
- HistoryReader、ReportEngine 和 CoachReader 读取同一历史集合，补录的实际组数、次数、重量与训练量正常进入统计；周报按实际结束日期归属。时长留空时不推断时长，不增加时长合计。
- 记录显示「手动补录」，仍可通过现有历史入口修改逐组记录或删除；不伪造每日状态或计划来源。
- 补录只收集实际结果，原定目标未提供：行内 actualOnly=true、reps=0 代表未知目标。表现分析不计算达标或自动进阶；AI 上下文将 target 标记为 not_recorded，met_sets 为 null，避免将实际次数当成原定目标。
- 所有补录组都表示实际做过的训练。未做过的组无需补录；历史修改仍支持现有的未完成原因与难度记录。

## 验证

ManualHistoryTest 覆盖实际快照、输入与数量边界、跨周归属、排序、SQLite 持久化和其他记录隔离、AI 上下文、动作搜索及多组保存、取消及草稿重建、非法保存、中英文页面。完整结果见 TESTING.md。

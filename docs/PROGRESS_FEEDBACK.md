# v0.4.0：训练反馈与下次建议

业务和界面继续使用 Java，数据继续使用 SQLite；新增功能在本地运行，无网络或 AI 服务依赖。

## 使用流程

1. 在训练页点击“记录第 N 组”，填写实际重量、实际次数和是否已训练。少于目标次数也应勾选“已训练”。
2. 选择难度：未填写、轻松、合适、吃力。未达目标或未训练时必须选择原因：时间不足、器械不可用、目标过难、身体不适、其他。未训练时实际次数必须为 0。
3. 提前结束时，为尚未记录的组选择统一原因。此前填写的每组数据及原因保留。可以保存零实际训练的原因记录；周报仍不把它计为一次完成训练。
4. 从历史列表、历史详情或周报进入“训练表现与下次建议”，选择动作，查看比较依据和建议。历史记录也可补填、修正难度和原因。
5. 生成下次计划时，动作卡片显示有关建议。符合条件的“每组目标增加 1 次”需要预览、确认；取消不会修改计划。

“已训练组”与“达标组”分别计算：例如目标 10 次、实际 8 次，计为已训练，未计为达标。总次数只累加确实已训练的组。

## 如何识别重量没变但有进步

分析以动作 ID 区分动作，避免同名自定义动作混合。只比较相同实际重量、相同计划组数及每组目标次数的记录；当次各已训练组重量必须一致，记录组数必须与计划一致。

| 上次 → 本次（均为 40 kg、3 × 10 目标） | 呈现 |
|---|---|
| 10/10/8 → 10/10/9 | 总次数 28 → 29，识别次数进步，达标仍为 2/3 |
| 10/9/8 → 10/10/7 | 总次数同为 27，达标组 1 → 2，识别完成情况进步 |
| 10/10/0 → 10/10/1 | 已训练组 2 → 3，次数增加，识别完成情况进步 |
| 同样完成，最高难度“吃力”→“合适” | 难度反馈改善；缺少难度时不作此结论 |
| 次数增加但达标组减少 | 提示变化不一致，建议复核，不直接认定进步 |

最近一次记录是分析起点，向前最多采用 7 次可比记录。页面展示上次日期、总次数、达标组、已训练组及难度的前后值。出现时间不足、器械不可用、缩短计划或替换动作时，显示情境影响，避免判成能力下降；身体不适优先提示审视安排，不提供进阶建议。混合重量、重复动作行及不一致组数显示暂不可比。

难度按当次已训练组的最高值概括；任一已训练组未填，整体难度显示“未填写”。这是一项记录比较功能，不是身体能力或恢复程度测量。

## 下次建议规则

- 仍未达到全部目标：保持可比条件，优先完成当前目标。
- 已完成目标、尚无足够稳定样本：重复当前安排并继续记录。
- 表现下降或指标变化不一致：提示核对目标和当日状态，不自动改重量。
- 时间或器械原因：建议检查可用时间、器械，并使用既有训练中调整功能。
- 最近连续 3 次同动作、同实际重量、同组数/次数目标，全部达标，且每组都有难度、均不超过“合适”：提供每组目标增加 1 次的可选建议，上限 20 次。期间任何不满足条件的记录都会中断连续计数。

生成计划沿用现有重量参考规则；建议不直接覆盖生成值。只有当前计划与分析条件一致、当日状态未触发减量，才提供增加次数按钮。确认时重新读取历史与状态，并检查计划未被其他操作修改。确认后重量和组数保持原值；已经开始的训练继续使用原快照。

“连续 3 次 + 每组 1 次”是可解释的课程产品规则，未经真实训练效果验证，不应在报告中写成医学结论或通用训练处方。规则强调个体状态；一般背景可参阅 [ACSM 2026 阻力训练指南说明](https://acsm.org/resistance-training-guidelines-update-2026/)，该来源不代表认可本项目的具体阈值。

## 技术与数据兼容

- `ProgressEngine`：独立 Java 数据模型、可比性检查、变化识别和建议规则。
- `ProgressReader`：把历史 JSON 转成分析样本；保留建议证据快照。
- `TrainingFeedback`：校验并复制每组反馈；结束时只填尚未处理的组。
- `ProgressScreen`：中英分析页面、数值比较和确认建议流程。
- `Store.saveSessionEdit/savePlanEdit`：事务内核对保存前快照，拒绝过期编辑；保存失败不污染原 JSON。
- `WorkoutAdjustments`：新增 `resolved` 状态。已填写“未训练及原因”的组不再是待安排组；后续缩短或替换保留这些记录。

逐组 JSON 增加 `effort`、`incompleteReason`、`resolved`、`feedbackVersion` 和 `recordedAt`；历史会增加 `endReason`。计划可保存 `progressAdvice` 和确认建议的证据。SQLite 表结构不变，不执行旧记录批量重写。

旧记录的难度、原因缺失时显示“未填写”；未训练组中预填的计划次数不作为实际次数。旧记录可参与有客观依据的次数/完成情况比较，无法满足难度完整的进阶规则。修改或删除历史后重新计算分析，过期建议在确认时拒绝应用。
